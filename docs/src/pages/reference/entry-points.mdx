# Reference — Entry Points

`@tevm/voltaire` publishes both ESM and CJS for every subpath, with `.d.ts`
declarations. The lists below come from the package's `exports` map.

## Root and backend entry points

| Subpath                  | Contents                                   |
| ------------------------ | ------------------------------------------ |
| `@tevm/voltaire`         | the barrel — portable JavaScript            |
| `@tevm/voltaire/wasm`    | WASM-backed implementations                 |
| `@tevm/voltaire/native`  | native FFI implementations                  |
| `@tevm/voltaire/functional` | functional-style variants                |
| `@tevm/voltaire/errors`  | typed error classes                         |

## What is in the barrel

`import { … } from '@tevm/voltaire'` re-exports the primitives, crypto, and
standards namespaces, plus `block`, `contract`, `evm`, `precompiles`, `stream`,
`transaction`, `wasm`, and the `brand` symbol.

It does **not** re-export `PrivateKey`, `PublicKey`, `Denomination`, `HDWallet`,
`Keystore`, or `KZG` — import those from their subpath.

## Tree-shaking

`sideEffects: false` is declared, and every module has its own entry, so a bundler
that follows `exports` will drop what you do not import. For the tightest
budgets, deep-import (`@tevm/voltaire/Address`) rather than destructuring the
barrel, and prefer the per-algorithm WASM modules in `wasm/crypto/` over the
combined `primitives.wasm`.

## Type declarations

Declarations ship in `types/` and are wired through both `exports.types` and
`typesVersions`, so `moduleResolution: "node16"`, `"nodenext"`, and `"bundler"`
all resolve. `abitype` is an optional peer dependency used for ABI type
inference.
