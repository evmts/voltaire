# ENS Security

An ENS name that looks right can resolve to an attacker's address. The defense is one rule: **normalize every untrusted name with `normalize()` before you hash, store, compare, or display it.** The hash functions do not do this for you.

## What the module enforces

| Threat | Enforced by | Result |
|--------|-------------|--------|
| Mixed-script homographs | `normalize`, `beautify`, `isValid`, `validate` | Rejected |
| Whole-script confusables | Same | Rejected |
| Disallowed invisible characters (ZWJ outside emoji, NUL) | Same | Rejected |
| Ignored invisible characters (zero-width space) | Same | Silently removed |
| Case and compatibility variants | `normalize` | Mapped to one canonical form |
| Look-alike separators (U+2024 one-dot leader) | Same | Rejected |
| Any of the above | `namehash`, `labelhash`, `from`, `is` | **Not checked** |

## Normalize before hashing

`namehash()` and `labelhash()` hash the exact UTF-8 bytes you pass. Two spellings of one name produce two different nodes:

```typescript
import * as Ens from '@tevm/voltaire/Ens';
import * as Hex from '@tevm/voltaire/Hex';

Hex.fromBytes(Ens.namehash("vitalik.eth"));
// "0xee6c4522aab0003e8d14cd40a6af439055fd2577951148c14b6cea9a53475835"

Hex.fromBytes(Ens.namehash("VITALIK.eth"));
// A different 32-byte value. No registry node matches it.

Hex.fromBytes(Ens.namehash(Ens.normalize("VITALIK.eth")));
// "0xee6c4522aab0003e8d14cd40a6af439055fd2577951148c14b6cea9a53475835"
```

`namehash` also skips empty labels, so `"a..eth"` hashes like `"a.eth"`. `normalize()` rejects `"a..eth"`. Skipping normalization turns a malformed name into a real-looking node.

## Homograph attacks

A homograph replaces a character with an identical-looking one from another script.

```typescript
import * as Ens from '@tevm/voltaire/Ens';

Ens.normalize("apple.eth");        // "apple.eth"
Ens.normalize("аpple.eth");   // throws: Cyrillic а (U+0430) mixed with Latin
Ens.isValid("аpple.eth");     // false
```

ENSIP-15 allows one script per label (with defined exceptions such as common punctuation and emoji). Mixing scripts throws `DisallowedCharacterError` with a cause message containing `illegal mixture`. Digits count too: `"1١.eth"` (ASCII 1 + Arabic-Indic 1) is rejected.

## Whole-script confusables

A label written entirely in one script can still look like a label in another:

```typescript
import * as Ens from '@tevm/voltaire/Ens';

// All Cyrillic: а р р е. Renders like Latin "appe".
Ens.normalize("арре.eth");
// throws: cause message contains "whole-script confusable: Cyrillic/Latin"
```

## Invisible characters

ENSIP-15 treats invisible characters in two ways. Know which applies:

```typescript
import * as Ens from '@tevm/voltaire/Ens';

// Zero-width joiner outside an emoji sequence: rejected
Ens.normalize("nic‍k.eth");   // throws: disallowed character {200D}

// Zero-width space: ignored and removed
Ens.normalize("vitalik.eth​"); // "vitalik.eth"

// NUL: rejected
Ens.normalize("invalid\x00.eth");   // throws: disallowed character {00}
```

Because ignored characters are removed, the raw input and the normalized output can differ in length and bytes. Always resolve and display the normalized output, never the raw input.

## Look-alike dots

Only U+002E separates labels. Characters that render as a dot are rejected rather than treated as separators:

```typescript
import * as Ens from '@tevm/voltaire/Ens';

Ens.normalize("nick․eth"); // throws: disallowed character "․" {2024}
```

## The brand is not a check

`from()` brands any string. `is()` accepts any non-empty string, including `" "` and `"VITALIK.ETH"`. Neither proves the name is safe. See [Branded Ens](/primitives/ens/branded-ens).

```typescript
import * as Ens from '@tevm/voltaire/Ens';

const unsafe = Ens.from("аpple.eth"); // typed Ens, never validated
Ens.namehash(unsafe);                       // hashes without complaint
```

## Display

- Show users the output of `normalize()` or `beautify()`, never their raw input.
- `beautify()` adds emoji presentation selectors and renders `ξ` as `Ξ` in non-Greek labels. It is for display only. Hash the `normalize()` output.
- Neither function detects names that are valid but merely similar (for example `vitalik.eth` and `vita1ik.eth`). Both are valid ASCII. Confirm the resolved address with the user.

## Checklist

1. Reject empty input yourself: `normalize("")` returns `""` without throwing.
2. Call `normalize()` on every user-supplied name and catch `DisallowedCharacterError`.
3. Hash only the normalized string.
4. Store and compare normalized strings.
5. Display `normalize()` or `beautify()` output, and show the resolved address.
