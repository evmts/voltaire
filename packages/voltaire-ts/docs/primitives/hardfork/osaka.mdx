## Overview

Osaka is the execution-layer half of the Fusaka upgrade (Fulu on the consensus layer). Voltaire sets `DEFAULT = OSAKA`, so APIs that take an optional hardfork use Osaka rules unless you pass another fork.

| Field | Value |
|-------|-------|
| Constant | `Hardfork.OSAKA` (`"osaka"`) |
| Mainnet activation | Dec 3, 2025 21:49:11 UTC |
| Timestamp | `1764798551` |
| Epoch | `411392` |
| Slot | `13164544` |
| Previous fork | `PRAGUE` |
| Next fork | `AMSTERDAM` (Glamsterdam) |

```typescript
import { Hardfork } from '@tevm/voltaire/primitives/Hardfork';

Hardfork.DEFAULT === Hardfork.OSAKA;                 // true
Hardfork.isAtLeast(Hardfork.OSAKA, Hardfork.PRAGUE); // true
Hardfork.fromString('osaka');                        // Hardfork.OSAKA
```

## BPO blob schedule

EIP-7892 lets clients raise blob limits without a named hardfork. Each BPO fork changes only the blob schedule and activates by timestamp.

| Fork | Timestamp | Target | Max | Base fee update fraction |
|------|-----------|--------|-----|--------------------------|
| Osaka | `1764798551` | 6 | 9 | `5_007_716` |
| BPO1 | `1765290071` (Dec 9, 2025) | 10 | 15 | `8_346_193` |
| BPO2 | `1767747671` (Jan 7, 2026) | 14 | 21 | `11_684_671` |

See [Blob schedules](/primitives/feemarket/blob-schedules) for the fee formulas.

## Gating on Osaka

```typescript
import { Hardfork, type HardforkType } from '@tevm/voltaire/primitives/Hardfork';

function hasP256Verify(fork: HardforkType): boolean {
  return Hardfork.isAtLeast(fork, Hardfork.OSAKA);
}

hasP256Verify(Hardfork.PRAGUE); // false
hasP256Verify(Hardfork.OSAKA);  // true
```

<Note>
Pass `Hardfork.PRAGUE` explicitly to reproduce pre-Osaka behavior, for example when replaying blocks before timestamp `1764798551`.
</Note>
