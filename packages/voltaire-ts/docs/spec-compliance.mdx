Voltaire verifies its TypeScript and Zig implementations against published Ethereum Execution Spec Tests (EEST), go-ethereum precompile fixtures, NIST/RFC cryptographic vectors, and Project Wycheproof edge cases across every Ethereum hardfork from Frontier through Osaka (Fusaka) and Amsterdam (Glamsterdam).

<Note>
Every entry below is backed by executable tests in [`src/spec-compliance.test.ts`](https://github.com/evmts/voltaire/blob/main/packages/voltaire-ts/src/spec-compliance.test.ts) and the dedicated precompile vector suites under `packages/voltaire-ts/src/evm/precompiles/`.
</Note>

## Wycheproof & Cryptographic Edge-Case Coverage

Voltaire's cryptography modules reject malleability, torsion, and invalid-curve edge cases tested by Google's Project Wycheproof and standard NIST/RFC suites:

| Primitive | Standard / Vector Suite | Verified Edge Cases |
|-----------|-------------------------|---------------------|
| **secp256k1** | Wycheproof ECDSA + EIP-2 | Low-`s` canonical enforcement (`s <= n/2`), zero & overflow scalars (`0`, `n`, `n + 1`, `2^256 - 1`), point-at-infinity `(0, 0)`, off-curve points, `x >= p`, public-key recovery |
| **P-256 (secp256r1)** | Wycheproof `ecdsa_secp256r1_sha256` (782 vectors) + SEC 1 v2 | Point-at-infinity `(0, 0)`, off-curve points, non-canonical coordinates `x >= p` / `y >= p`, invalid SEC1 prefixes (`0x06`/`0x07`), zero/overflow scalars, high-`s` acceptance per EIP-7951 |
| **Ed25519** | RFC 8032 Section 7.1 + Wycheproof EdDSA | RFC 8032 exact keypair & signature vectors, rejection of all 8 Curve25519 small-order torsion points (orders 1, 2, 4, 8), non-canonical `y >= 2^255 - 19`, signature scalar `S >= L` |
| **SHA-256** | FIPS 180-4 | Empty, `"abc"`, multi-block 448-bit padding boundary |
| **Keccak-256** | Ethereum Yellow Paper | Pre-NIST `0x01` domain padding (`""`, `"abc"`, `"testing"`), distinct from SHA3-256 |
| **RIPEMD-160** | ISO/IEC 10118-3 | Empty, `"a"`, `"abc"`, `"message digest"`, `"abcdefghijklmnopqrstuvwxyz"` |
| **BLAKE2b** | RFC 7693 Appendix A | BLAKE2b-512 and BLAKE2b-256 (`""`, `"abc"`) |

## Application Standards & Proof Primitives

| Standard | Description | Verified Vectors |
|----------|-------------|------------------|
| **EIP-55** | Mixed-case checksummed Ethereum addresses | Official 8-address EIP-55 test vector set + invalid case-flip rejection |
| **EIP-191** | Signed data standard (`0x00`, `0x01`, `0x45` personal sign) | Prefix framing, personal-message digest, secp256k1 signature recovery |
| **EIP-712** | Typed structured data hashing & signing | Official `"Ether Mail"` domain separator, `Mail` struct hash, final digest (`0xbe609aee...`) |
| **EIP-1186** | Merkle Patricia Trie account/storage proofs | Empty trie root (`0x56e81f17...`), Yellow Paper leaf root, 32-byte state-trie inclusion proofs, non-inclusion proofs, tampered-node rejection |
| **EIP-1191** | Chain-ID-specific checksummed addresses | Official RSK Mainnet (chain `30`) & Testnet (chain `31`) domain-separated checksum vectors |
| **ERC-8010** | Pre-delegation EIP-7702 signature wrapper | Wrap/unwrap round-trip with `0x8010...8010` 32-byte magic trailer, optional initializer (`to`/`data`), malformed envelope rejection |

## Running the Compliance Suite Locally

Run the unified EEST + Wycheproof compliance suite:

```bash
pnpm --filter @tevm/voltaire exec vitest run src/spec-compliance.test.ts
```

Run the full precompile and hardfork vector suites alongside it:

```bash
pnpm --filter @tevm/voltaire exec vitest run \
  src/spec-compliance.test.ts \
  src/evm/precompiles/bn254_precompiles.test.ts \
  src/evm/precompiles/eip2537.vectors.test.ts \
  src/evm/precompiles/p256verify.test.ts \
  src/evm/precompiles/modexp.osaka.test.ts \
  src/primitives/FeeMarket/BlobSchedule.test.ts \
  src/primitives/BlockAccessList/BlockAccessList.test.ts \
  src/primitives/ExecutionPayloadBid/ExecutionPayloadBid.test.ts \
  src/evm/bitwise/0x1e_CLZ.test.ts
```

Run the Zig core compliance tests as well:

```bash
zig build test
```
