Voltaire separates wire-level primitives (`@tevm/voltaire/provider`, `@tevm/voltaire/jsonrpc`) from higher-level client abstractions (provided as copyable [Skills](/skills)). This page compares tradeoffs across raw EIP-1193, ethers.js v6, viem, and Voltaire.

## Feature Matrix

| Dimension | Raw EIP-1193 | ethers.js v6 | viem | Voltaire |
| --- | --- | --- | --- | --- |
| Primary abstraction | `provider.request({ method, params })` | `JsonRpcProvider` class with named methods | `createPublicClient` + action functions | `TypedProvider<TSchema>` + `Rpc.*` builders + Skills |
| Primitive representation | Plain strings | Custom classes / strings | Hex strings + `bigint` | Branded `Uint8Array` / `string` (zero wrapper allocation) |
| Compile-time RPC typing | None | Fixed method signatures | Full schema-driven typing | Full `RpcSchema` / `VoltaireRpcSchema` typing |
| Tree-shaking | N/A | Partial (class-based) | Full (action functions) | Full (module subpaths + `sideEffects: false`) |
| Built-in local EVM / fork | None | None | Anvil via external process | `InMemoryProvider`, `ForkProvider`, `fromEvm` |
| Native / WASM crypto | None | JS only | JS (`@noble/*`) | JS, WASM (`@tevm/voltaire/wasm`), and Zig FFI (`@tevm/voltaire/native`) |
| Multi-language parity | N/A | TypeScript only | TypeScript only | TypeScript, Effect, Zig, Rust, Go, Python, Swift, C |
| Customization model | Manual | Subclassing | Custom transports / actions | Copyable [Skills](/skills) in your codebase |

## Code Comparison

### Raw EIP-1193 vs Voltaire Request Builders

```typescript
// Raw EIP-1193: untyped method name and parameter array
const rawBalance = await provider.request({
  method: 'eth_getBalance',
  params: ['0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb0', 'latest'],
});

// Voltaire: validated Address primitive + typed request builder
import { Address } from '@tevm/voltaire/Address';
import { Rpc } from '@tevm/voltaire/jsonrpc';

const account = Address('0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb0');
const balance = await provider.request(Rpc.Eth.GetBalanceRequest(account, 'latest'));
```

### Migrating from ethers.js or viem

If an existing codebase already uses ethers v6 or viem conventions, adopt Voltaire primitives incrementally with drop-in Skills instead of rewriting call sites:

- **ethers.js v6**: [ethers-provider](/skills/ethers-provider), [ethers-contract](/skills/ethers-contract), [ethers-signer](/skills/ethers-signer), [ethers-interface](/skills/ethers-interface)
- **viem**: [viem-publicclient](/skills/viem-publicclient), [viem-walletclient](/skills/viem-walletclient), [viem-contract](/skills/viem-contract), [viem-account](/skills/viem-account)

## When to Choose Voltaire

- You want direct JSON-RPC control without hidden retries, silent multicalls, or opaque nonce caching.
- You need strict nominal typing so `Address`, `Hash`, `Hex`, and `Bytes32` cannot be swapped at compile time.
- You need deterministic local EVM execution (`InMemoryProvider`, `ForkProvider`) or optional Zig/WASM acceleration for hashing, secp256k1, BLS12-381, BN254, and KZG.
- You share Ethereum primitives across TypeScript and systems languages (Zig, Rust, Go, Python, Swift, C).
